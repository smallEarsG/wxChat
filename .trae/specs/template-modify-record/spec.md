# 自定义模板修改记录功能 - 产品需求文档

## Overview
- **Summary**: 实现自定义模板保存时自动记录修改日志，并支持从修改记录列表跳转到对应的自定义模板进行编辑
- **Purpose**: 为用户提供完整的模板修改追溯能力，方便追踪模板变更历史并快速定位和编辑特定版本的模板
- **Target Users**: 使用自定义模板功能的所有用户

## Goals
- [x] 自定义模板保存时自动生成修改记录
- [x] 修改记录列表展示模板变更历史
- [x] 支持从修改记录跳转到对应的自定义模板编辑页面
- [x] 修改记录包含模板名称、修改时间、操作类型等关键信息

## Non-Goals (Out of Scope)
- 模板版本回滚功能
- 修改记录的批量操作
- 修改记录的搜索和筛选

## Background & Context
当前系统已实现：
- 自定义模板管理（创建、编辑、删除、预览）
- 修改记录页面（收款通知、提现通知记录）

需要新增：
- 模板修改记录的自动创建
- 修改记录与模板的关联
- 从记录跳转到模板的导航能力

## Functional Requirements
- **FR-1**: 保存自定义模板时，自动生成一条模板修改记录
- **FR-2**: 修改记录页面展示模板修改记录列表
- **FR-3**: 点击模板修改记录可跳转到对应的模板编辑页面
- **FR-4**: 修改记录包含操作类型（新增/编辑）、模板名称、修改时间、模板ID等信息

## Non-Functional Requirements
- **NFR-1**: 记录创建性能：模板保存时记录创建延迟 < 100ms
- **NFR-2**: 数据一致性：模板删除时对应的修改记录也应被清理

## Constraints
- **Technical**: 基于 UniApp 框架，使用本地存储（uni.setStorageSync）持久化数据
- **Dependencies**: 依赖现有的自定义模板数据结构和修改记录页面

## Assumptions
- 用户已熟悉自定义模板和修改记录的基本操作
- 本地存储有足够空间存储修改记录

## Acceptance Criteria

### AC-1: 保存模板时自动创建修改记录
- **Given**: 用户在模板配置页面编辑或新建模板
- **When**: 用户点击"保存"按钮并成功保存
- **Then**: 系统自动创建一条模板修改记录到本地存储
- **Verification**: `programmatic`

### AC-2: 修改记录展示模板变更信息
- **Given**: 用户进入修改记录页面
- **When**: 页面加载完成
- **Then**: 页面展示模板修改记录，包含操作类型、模板名称、修改时间
- **Verification**: `human-judgment`

### AC-3: 从修改记录跳转模板编辑
- **Given**: 用户在修改记录页面看到模板修改记录
- **When**: 用户点击该记录
- **Then**: 跳转到对应的模板配置页面并加载该模板数据
- **Verification**: `programmatic`
